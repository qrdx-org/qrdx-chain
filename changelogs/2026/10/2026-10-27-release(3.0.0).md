**release(3.0.0): mainnet-readiness fixes, bridge refunds and guardrails, PQ smart accounts**

**Date**: 2026-10-27

---

## Before upgrading

* **A new genesis.** New chain-spec parameters (`BRIDGE_DEPOSIT_WINDOW`, `BRIDGE_MINT_LIMITS`,
  `EVM_PREDEPLOYS`)
  and features (`slot_timestamps`, `evm_standard_precompiles`, `validator_state_root`,
  `exchange_inclusion`, `evm_conformance`) change every spec's genesis hash.
  A database from 2.x refuses to start, by design (docs/PROTOCOL_UPGRADES.md).
* **Validator keys must be encrypted** outside dev networks. Convert a plaintext wallet with
  `python scripts/validator/keystore.py encrypt`, and set `QRDX_VALIDATOR_PASSWORD_FILE`
  (docs/VALIDATOR_KEYS.md).
* **liboqs 0.16.0 and liboqs-python 0.16.0.1.** Rerun `.devcontainer/install-liboqs.sh`. A node
  whose library does not compute FIPS 204/203 refuses to start.
* **Validators listen for 3 epochs after a start** before signing (the doppelganger check;
  `QRDX_DOPPELGANGER_EPOCHS`, 0 on dev networks).
* **Grafana needs `GRAFANA_ADMIN_PASSWORD`**: there is no default any more.

## Security

* **Slashing protection in the running validator.** Every block and vote is recorded before it
  is signed, in a locked record of its own, with EIP-3076 export and import, plus the
  doppelganger check. Fixes a mid-epoch restart signing a second, slashable vote.
* **Encrypted validator keystores:** scrypt and AES-256-GCM, bound to the key's identity.
* **No silent fallback to round-3 Dilithium/Kyber.** A known-answer test proves the installed
  library computes ML-DSA-65 and ML-KEM-768.
* **Block timestamps are their slot's start time** (`slot_timestamps`). A proposer could set the
  exchange's clock before.
* **EVM:** an up-front gas check (a payer's balance could go negative), and the PQ precompiles
  moved off Ethereum's addresses (`evm_standard_precompiles`).
* **Blocks carry only exchange transactions that run** (`exchange_inclusion`).
  * **Before:** a transaction whose payer could not cover its gas was admitted, selected and
    carried in a block without executing, paying or consuming its nonce. It could be carried
    again, from any number of free accounts.
  * **Now:** admission checks the payer's balance. The proposer judges its whole selection
    before running it. A block carrying a transaction that would be refused before it runs is
    invalid. Each payer's fees are reserved before anything in the block runs.
* **No proof-of-work block is accepted.** The inherited miner path was still reachable:
  `/push_block`, peers' block submission, and sync for a block without a proposer. It judged a
  block by proof-of-work rules alone. Every 512 blocks those expected difficulty 1.0, and only a
  database type error stopped a block mined against the tip from being appended. All of them
  refuse it now (`/push_block` answers 410). Balances no longer fall back to the legacy UTXO
  table.
* **Snapshot restores verify contract code**, which the state root covers only by hash, and take
  block 0's records from the node's own genesis.
* **A block built to parse slowly is refused unparsed.** Any peer could submit block content
  that took seconds to parse, several times over, with the block-processing lock held. Content
  is now refused unparsed if it has more structure than a block can carry, and it is parsed
  once (docs/BLOCK_LIMITS.md).
* **The DHT store is bounded** (1,024 entries). `dht_message` needs no identity.
* **A refused EVM transaction stays refused when sent again.** It used to be answered as
  admitted, and every refusal was logged at ERROR with a traceback.
* **Attacks on a live network** (`integration_tests/adversarial.py`, nightly): an equivocating
  proposer, a block built to parse slowly, and a transaction flood.
* **The RPC limiter:**
  * a caller's own limit is checked first;
  * peers have a pool that public traffic cannot spend;
  * callers that are not peers are limited by address;
  * a JSON-RPC batch holds at most 100 calls and costs one token per call. It used to cost one
    request at any size.
* **Shadow verification by OpenSSL** (`QRDX_PQ_SHADOW_VERIFY`; docs/PQ_CRYPTO_BACKEND.md):
  every ML-DSA-65 signature is checked by both libraries, and any disagreement is counted.
* **The EVM follows Ethereum** (`evm_conformance`; docs/EVM_CONFORMANCE.md). Ethereum's state
  tests are now run against it in CI, and they found the differences fixed here:
  * the intrinsic gas comes out of the gas limit and is paid on top of execution; it was a
    floor, so calldata and a 0x51 signature check were free whenever a transaction executed more;
  * the gas limit is bought up front, and the unused part comes back with EIP-3529's refund;
  * the sender and recipient start warm;
  * a creation checks for an account at its address;
  * MODEXP of an empty base is correct;
  * 0x0202 reverts.
* **Fuzzing of every decoder peers and users reach** (`tests/test_fuzz_decoders.py`), in CI. It
  found the two issues above, and decoders raising errors their callers did not catch.
* **A peer must earn its place in the peer table.** Any signed request that named the chain's
  genesis used to make its caller a peer, so throwaway keys could fill the table and hold it.
  * Only a completed handshake admits a peer; a stranger is dialed back instead.
  * At most `QRDX_PEERS_PER_SUBNET` (default 4) peers come from one /24 or /48.
  * A full table evicts the newest inbound peer of the most crowded network. It never evicts
    a validator, a peer this node dialed, or the longest-connected peers.
  * A validator proves itself with its validator key (`peer-validator` signing domain).

## Wallets

* EIP-1559 and EIP-2930 transactions. Block headers report the real gas limit, base fee, state
  root and log bloom. The suggested tip is 0.
* Ethereum accounts trade on the exchange through a PQ agent they approve from MetaMask.
* PQ smart accounts in the EVM (`contracts/accounts/`): a factory, ERC-1271, session keys,
  guardian recovery. The implementation (`0x…0600`) and the factory (`0x…0601`) are predeployed
  at genesis (chain-spec parameter `EVM_PREDEPLOYS`): deploying them took more gas than a block
  holds.
* **A TypeScript SDK** (`sdk/typescript`, `@qrdx/sdk`):
  * ML-DSA-65 keys through `@noble/post-quantum`, interoperable with liboqs;
  * exchange transactions signed to the node's exact bytes;
  * type-0x51 transactions;
  * smart accounts: create, `execute`, ERC-1271, sessions and recovery;
  * a JSON-RPC client.

  It is tested against vectors the node computes.

## Bridge

* **Deposits can be proven.** Anyone mints a deposit with a storage proof of the lockbox's record
  against an attested finalized head (`BRIDGE_PROVE_DEPOSIT`, `scripts/bridge/prove_deposit.py`).
  Validators may attest heads only (`QRDX_BRIDGE_DEPOSIT_VOTES=0`). Needs `BRIDGE_LOCKBOXES`.
* **Lockbox v3.** Deposits get ids and storage records. A refund is checked by the contract: a
  recorded deposit, whole, to its depositor, after `refundDelay`.
* The deposit window, lockbox refunds and custodian refund tooling.
* Per-asset mint limits (required on real networks) and a governance mint pause.
* The watcher takes turns through deposits and skips malformed chain heads.

## Quantum migration and the Doomsday Protocol

docs/QUANTUM_MIGRATION.md.

* **Migration.** An Ethereum account binds a post-quantum successor as its controller:
  * on QRDX, through account control;
  * on Ethereum, through `QRDXMigrationRegistry`, proven with `MIGRATION_CLAIM`
    (`scripts/migration/claim_successor.py`). Needs `MIGRATION_REGISTRIES`.
* **Doomsday.** Triggered by a proof that a hash-derived canary signed (`DOOMSDAY_PROVE`,
  `scripts/doomsday/canary.py`; needs `DOOMSDAY_CANARIES`), or by governance's
  `declare_quantum_emergency`. Once triggered:
  * ECDSA transactions are refused, and `ECRECOVER` recovers nothing;
  * agents of `0x` accounts are revoked;
  * the bridge stops;
  * later commitments bind nothing.

  Read the state with `bridge_getDoomsday`; the alert is `DoomsdayTriggered`.
* `TOKEN_TRANSFER` moves native QRDX (`token_address: "QRDX"`), so an account's controller can
  move it.

## Checkpoint sync and pruning

docs/CHECKPOINT_SYNC.md.

* **The validators' state is in the root** (feature `validator_state_root`, from genesis on new
  networks). The root commits to the epoch's validator set and a hash chain of the staking
  logs. State proofs and the `0x…0300` precompile carry the validator root as one more part.
* **Snapshots.** `scripts/node/snapshot.py create` copies a node's database. `fetch` downloads a
  published one from any HTTP server, resumably. `restore`:
  * rebuilds genesis from the genesis file;
  * hash-verifies history up to a trusted checkpoint (`--checkpoint height:hash`);
  * recomputes every root at the exchange checkpoint, which must equal the signed one;
  * refuses anything else, including a pickle naming code.
* **Nodes publish snapshots** (`QRDX_SNAPSHOT_DIR`): the newest, at each exchange checkpoint.
  It is served at `/snapshot/`, resumably, and advertised in `p2p_getStatus`; the node's own
  tables are left out. `snapshot.py fetch --peer URL` takes the newest one the given nodes
  publish.
* **History pruning.** `QRDX_HISTORY_RETENTION_BLOCKS` (at least 4,096; unset: archive). It drops
  the signatures and sections of blocks behind finality. A pruned node cannot replay from
  genesis or serve old blocks.

## Performance

* **Exchange transactions are gossiped in batches:** what a node admitted in the last 50 ms goes
  to each peer in one signed request. Under load, one request per transaction per peer delayed
  blocks enough to fork the chain; batching doubled the rate sustained at full block rate
  (docs/PERFORMANCE.md).
* **`integration_tests/load.py`** measures throughput, inclusion latency and the block rate under
  load, with a profile of each step.
* **Twice the block pipeline per core** (docs/PERFORMANCE.md): about 4,450 transfers a second
  through proposing and importing a block, up from about 2,190.
  * Balances are read and written in batches, held to the one-row forms by a differential
    test.
  * An importer verifies a block's signatures once, across a thread pool (it verified them
    twice).
  * Per-transaction derivations are cached.
* **Peers' gossip is no longer refused under load.** Each peer was held to the public
  per-address limit (50 calls a second), and gossip is a call per transaction per peer. From
  about 50 transactions a second, gossip, blocks and votes were refused. Peers now have their
  own limits, sized for the protocol's rate: `QRDX_RPC_PEER_RPS` (per peer, 4,000) and
  `QRDX_RPC_PEER_POOL_RPS` (all peers, 16,000).
* **Higher exchange capacity** (docs/BLOCK_LIMITS.md).
  * `BLOCK_EXCHANGE_GAS_LIMIT` is 80,000,000 for new networks (was 20,000,000): 4,000
    transfers a second sustained, 8,000 in bursts.
  * It is height-aware: a fork raises it on a running network. Existing networks keep the
    limit their genesis committed to.
  * A proposer fills what it runs in 40% of a slot (`QRDX_EXCHANGE_BUILD_SHARE`), so its block
    and every import of it fit the slot.
* **Blocks travel compact:** their exchange operations as hashes, rebuilt from each peer's
  mempool and checked against the signed `body_root` (`qrdx/node/block_relay.py`).
* **Gossip is pushed once and announced after** (`exchange_announceTransactions`). It is no
  longer re-sent whole by every relay to every peer, nor capped at about 1,280 a second.
* **A native module, in Rust** (`native/qrdx-native`; docs/NATIVE.md). It checks signatures
  in parallel with the same liboqs (2,000 in 7 ms, against 130 ms) and writes a block's body
  root. Its output is the Python paths' byte for byte, and the node runs without it
  (`QRDX_NATIVE=0`).
* **A transaction is verified once,** at admission, and then recognized in the block that
  carries it.
* **The HTTP stack:**
  * uvicorn's C parser and event loop (`httptools`, `uvloop`);
  * `POST /rpc` past the request middleware;
  * transport JSON written by orjson.
* **Measured live:** 300 transfers a second fills nearly every slot, and the ceiling on one host
  rose from about 250 a second to about 450 (docs/PERFORMANCE.md).
* **Cheaper peer requests.** A request is signed over the SHA-256 of its bytes, not over a
  re-encoded copy. A block is encoded and signed once for all peers, not once per peer. Both
  signature forms are accepted.

## Operations

* **The image builds the native module** against its own liboqs. The Rust toolchain is pinned
  (1.86.0, installer by sha256), and so is every crate (`Cargo.lock`).
* **`qrdx/node/main.py` split by concern** (docs/NODE_LAYOUT.md), from 8,904 lines to 1,215:
  `block_import`, `evm_runtime`, `derived_state`, `fork_choice`, `sync`, `peers`, `discovery`,
  `chain_identity`, `security`, and the REST API in `qrdx/node/api/`. Routes, parameters,
  middleware and rate limits are unchanged.
* Alert rules that read real metrics, validator, bridge and oracle gauges, a provisioned Grafana
  dashboard, and a scheduled reconcile.
